# Expose per-node policy through the engine API

Implemented 2026-11-12 as part of the `flow-plan/2` migration.

## Pain

- The GUI applied `retries`, `retry_delay_seconds`, and `timeout` by mutating
  `NodeFunction` attributes, which upstream did not support.
- Per-node policy was reported by the plan document but could not be imported
  back into a run.

## Change

- `RunOptions.node_policies: dict[str, NodePolicy]` is a public engine option.
- `NodeFunction._effective_policy()` precedence is now plan policy > explicit
  `@node` keyword > `RunOptions.node_defaults` > built-in default.
- `execute_plan` builds `node_policies` from the document's
  `nodes[].policy`, so a plan file is a supported policy import path.
- The GUI writes policy edits into `state.plan.nodes[].policy`; no private
  attribute mutation remains.

## Acceptance

- A policy edit takes effect through a public API with no private attribute
  writes.
- Covered by engine policy-precedence tests and GUI plan execute tests.
